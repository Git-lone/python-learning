## 一道系统设计题

**练习设定：** 做一个企业客服工单助手，支持知识查询与回复草稿；发送给客户前必须由有权限的人工确认。系统可能超时或重启，多租户数据不能相互泄露。

**前 3 分钟，先问边界：** 用户是谁，允许读哪些资料，哪些动作禁止自动执行，日请求量/峰值如何，响应时间与费用预算是什么，何时必须转人工，敏感信息能否发送给模型供应商？没有数据就明确假设，不编造现有 QPS。

**接下来画文字链路：** 身份认证 -> 请求校验 -> 按权限检索 -> 生成带证据的草稿 -> 规则/质量校验 -> 保存待审批状态 -> 人工确认 -> 幂等业务执行 -> 审计结果。模型不能自行扩大权限或修改已经审批的载荷。

**再谈异常：** 无证据拒答；模型超时停止并保留可诊断状态；审批拒绝不发送；执行超时未知结果先查业务状态，不直接再发；服务重启从 checkpoint 恢复；多个 worker 对同一运行使用单写者/租约。

**最后谈验证：** 请求与对象级授权测试、重复提交、旧审批重放、流式断开、检索负例；分开报告召回、回答正确、工具执行成功和端到端业务成功；灰度对比固定版本，失败时回退到人工草稿。

当前项目只分别实现只读 API、合成 MCP 查询、合成发布工作流与检索基线。把它们连接成真正工单助手是[作品集扩展](PORTFOLIO.md)，不能描述为当前已经端到端上线。

## 一个可诚实使用的回答示范

> 我原来的经验是 Java 后端，最近用 Python 做了一个 Agent 工程练习项目。前面的手写循环帮助我理解工具调用和终止条件；需要暂停恢复时，我用了 LangGraph 和 SQLite。恢复时节点可能重跑，所以把审批放在写操作之前，在业务表用请求 ID 做唯一键，并验证重复请求与载荷冲突。现在跑的是合成数据和本地服务，还没有生产多租户认证和外部消息投递。下一步会接入真实身份系统与脱敏评测集，验证完整链路。

只有自己实际读懂、运行并能解释这些实现后，才使用这种表述；已有生产经历就用自己的真实证据替换。不要把教程生成的代码说成全部独立从零设计。

## 模拟面试安排

| 环节 | 时间 | 评分点 |
|---|---:|---|
| 项目介绍 | 5 分钟 | 背景、个人贡献、输入输出、边界 |
| 追问 | 15 分钟 | 从状态、失败、权限、成本选三项深入 |
| 编码 | 20 分钟 | 从使用率校验、滑动窗口、限并发调用选一题；写测试 |
| 系统设计 | 15 分钟 | 先澄清，再拆解，再说明验证与取舍 |
| 反问 | 5 分钟 | 岗位偏应用/平台/模型，生产阶段、评测方式和事故责任 |

每题各按 0～2 分记录：概念准确、实现细节、取舍理由、可验证证据、边界诚实，总计 10 分。这只是自评量表，不是公司评分标准。错题记录包含日期、问题、自己的原回答、缺口、修复实验和复测结果。
