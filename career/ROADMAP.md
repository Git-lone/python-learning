# Java 开发转 Agent 应用开发：学习路线

目标是 Python Agent 应用/后端工程岗位：能读写业务代码、接入模型与工具、设计可靠执行流程、做评测并提供可运行服务。不等同于模型训练、推理引擎、GPU 算子或研究岗位，也不承诺学完即可获得 offer。

## 先做诊断

不看参考答案完成第 8、10、11 章练习。能否解释可变默认参数、生成器、上下文管理、async 取消与阻塞区别？能否独立写出包含异常路径的 pytest？不会就补前 11 章，不必因为会 Java 而跳过 Python 运行机制。

| 能力 | Java 经验可迁移处 | Python / Agent 必补 | 交付证据 |
|---|---|---|---|
| 工程基础 | 接口、异常、分层、测试 | Protocol、类型提示、包、venv、pytest | 第 1～11 章验收 |
| 并发与网络 | 线程池、超时、重试 | asyncio、异步生成器、取消、事件循环阻塞 | 第 10、13、19 章失败用例 |
| 模型应用 | 外部服务适配 | token、上下文窗口、结构化输出、流式完成语义 | 第 14、15、19 章 |
| Agent 执行 | 状态机、任务调度 | 工具循环、预算、暂停恢复、审批 | 第 17、18、21 章 |
| 知识与记忆 | 数据建模、索引、权限 | 检索切分、RAG、记忆生命周期、评测 | 第 16、22 章 |
| 协议与 API | RPC、认证、Controller | MCP、Pydantic、FastAPI、SSE | 第 20、23 章 |
| 生产质量 | 幂等、观测、回滚 | 用量核算、工具安全、失败分桶、模型回归 | 第 24 章与作品集 |

## 六个阶段，而非强制六周

每天约 1～2 小时可以把它当作六周计划；有短板就延长，不按日历假装掌握。

1. **Python 上手：** 第 1～11 章，做任务报告器。输出一次从 Java 实现翻译成 Python 后的差异解释，尤其是数据可变性和异常处理。
2. **服务与模型边界：** 第 12～15、19 章。给异步调用补超时与故障测试；了解 token、采样、上下文和结构化输出验证。真实 API 仅在自备凭据、确认费用后运行。
3. **RAG 与评测：** 第 16、22 章。给 5 条合成题扩成独立数据集，标记检索失败原因。向量、混合、重排是待做实验，不能只在架构图里出现。
4. **执行与协议：** 第 17、18、20、21 章。演示一次失败工具、一次暂停、一次重启恢复、一次拒绝、一次重复请求。
5. **服务化与工程：** 第 23、24 章。请求校验、权限、日志脱敏、流式错误合同；做断网/超时实验，再设计真实认证和任务队列。
6. **作品集与面试：** 按[作品集](PORTFOLIO.md)完成一个自己的扩展；用[真实面经](INTERVIEW_EXPERIENCES.md)逐题模拟，准备 2 分钟与 8 分钟两版项目介绍。

## 需要懂，但此教程不是专门训练课程

- Transformer/attention、预训练/SFT/偏好对齐：能解释大意和应用限制，不把 RAG 描述成模型重新训练。
- embedding、向量相似度与 ANN：理解索引召回和业务相关性的区别，实际完成一个向量检索实验后再写“熟练”。
- 模型微调：如果岗位 JD 要求 LoRA、训练数据、GPU 或推理优化，另补对应实战；本项目没有这些成果。
- 算法和后端基础：保留哈希表、滑动窗口、堆、树、数据库索引、事务、HTTP 和缓存的一般编码能力。

## 判定是否达到投递准备线

你应该能在陌生机器上按 README 启动；不用参考答案完成关键练习；解释一次失败请求在哪一层出错；对每个简历指标指出原始样本、版本与计算方式；清楚讲出至少三项尚未实现的能力。

具体岗位要求以目标职位的当前 JD 为准。这条路线是教程编排建议，不是对所有厂商招聘规则的归纳。
