# Java 开发转 Python Agent 应用：10 周学习路线

**目标：** 能独立做一个有模型调用、检索、工具、Agent Loop、Harness 控制和评测的 Python 后端应用，并能解释每层的职责与失败处理。目标岗位是 Agent 应用开发或 Python 后端；模型预训练、GPU 推理优化不在这条主线内。

**时间假设：** 每周 8～10 小时，连续 10 周。每周约 3 小时读课程、4～5 小时自己编码、1～2 小时做测试与复盘。时间不足时按“过关标准”延长，不必赶日历。Java 的接口、异常、测试与服务设计经验可以迁移；Python 运行机制、LLM 输出不确定性和 Agent 循环需要亲手验证。

## 一个项目贯穿 10 周

做一个**售后工单助手**。输入客户工单，先分类，再从授权的政策文档中查证据，必要时用只读工具查询模拟订单，最后生成“建议与依据”。它只起草退款申请；实际退款必须由业务规则与人工审批决定。

每周在同一项目上增加一层能力，并保留前一周的测试。代码要给重要边界、异常处理和不明显的决策写注释；不要把逐行翻译成中文当作注释。

## 第 1～2 周：Python 写得顺手

| 周次 | 学习与编码 | 当周产物 | 过关标准 |
|---|---|---|---|
| 1 | 先独立尝试[本仓库第 1～5、8 章](../INDEX.md)的关键练习；按薄弱处读 Python-100-Days 的变量、列表/字典、函数、类。写一个接收 JSONL 工单并按规则分类的 CLI。 | `tickets.jsonl → 分类结果.jsonl`，附 5 条正常与异常输入。 | 能解释可变对象、默认参数、字典与 `dataclass` 的区别；坏输入有明确报错，不静默丢数据。 |
| 2 | 读 Python-100-Days 的文件和异常部分；练[本仓库第 6～13 章](../INDEX.md)中的包、类型提示、上下文管理、`asyncio`、`pytest`、HTTP。把 CLI 拆成输入、业务、输出三层。 | 包结构、类型标注、日志和 pytest；一个异步外部客户端替身。 | 不看答案写出正常、超时、取消与坏 JSON 测试；说明 `async` 函数里直接阻塞会发生什么。 |

**阶段检查：** 能把一个熟悉的 Java `Service + Client + DTO` 设计用 Python 的模块、`Protocol`、数据类和异常边界表达出来。若第 2 周的异步与测试还不稳，先补再进入模型调用。

## 第 3～5 周：LLM 应用、结构化输出、RAG

| 周次 | 学习与编码 | 当周产物 | 过关标准 |
|---|---|---|---|
| 3 | 读微软课程 01、02、04 和[本仓库第 14 章](../chapters/14-llm-application-basics/README.md)。弄清 token、角色消息、上下文、推理与训练。把关键词分类器改成 `ModelClient` 端口，先接离线替身。 | 客服意图分类接口、消息构造和一组包含否定句的标注样本。 | 能指出关键词的漏判/误判；能解释提示词为什么不是输出合同。 |
| 4 | 读微软课程 06、11；练[第 15、19 章](../INDEX.md)。实现 JSON 解析、字段类型和值域检查、超时与错误分类；真实 SDK 只作为可选适配器。 | `raw model text → validated intent`，至少覆盖坏 JSON、缺字段、未知标签与调用超时。 | 任一失败都不会伪装成合法的 `other`；离线测试可重复运行。 |
| 5 | 读微软课程 08、15；练[第 16、22 章](../INDEX.md)。准备少量售后政策文档，做切分、检索、引用和无证据拒答；先用简单检索基线，再考虑向量检索。 | 回答中带文档 ID；20 条有标签的检索/问答样本。 | 能分开统计“没检索到”和“检索到了但回答错”；无证据时不编造政策。 |

**阶段检查：** 同一条工单能走完 `输入 → 分类 → 检索 → 有依据的草稿`。不要把 RAG 说成微调，也不要把模型自报的 `confidence` 当作已校准概率。

## 第 6～8 周：Agent Loop 与 Harness

| 周次 | 学习与编码 | 当周产物 | 过关标准 |
|---|---|---|---|
| 6 | 读 Hello-Agents 第 1、3、4 章和 Learn Claude Code [s01 Agent Loop](https://github.com/shareAI-lab/learn-claude-code/tree/main/s01_agent_loop)、[s02 Tool Use](https://github.com/shareAI-lab/learn-claude-code/tree/main/s02_tool_use)；练[本仓库第 17 章](../chapters/17-ai-agent-engineering/README.md)。先手写“模型决定 → 工具执行 → 观察结果 → 再决定”的循环。 | 只读 `search_policy`、`get_order_stub` 两个工具和最小 Loop。 | 能展示一次工具调用、一次工具失败、一次无工具调用而停止；能解释它与固定工作流的区别。 |
| 7 | 读 Learn Claude Code s03、s04、s08；练[第 18 章](../chapters/18-agent-harness-loop/README.md)。给循环加入工具白名单、参数校验、步数/时间预算、拒绝与日志；观察上下文增长。 | Harness 控制层与失败路径测试。 | 越权工具不执行；达到预算会停止并返回原因；长对话能解释保留与压缩了什么。 |
| 8 | 读 Learn Claude Code s14～s17；练[第 20、21 章](../INDEX.md)。接一个本地 MCP 只读工具，保存运行状态，演示中断后恢复和人工审批。 | 可恢复的一次工单处理轨迹。 | 重启后不会重复执行已完成动作；审批拒绝后不会继续执行；能区分“循环继续”和“目标已达成”。 |

**阶段检查：** 不依赖框架也能画出并写出最小 Agent Loop；能说明工具层、权限层、状态层为什么属于 Harness。框架可在理解机制后再接入。

## 每周固定的学习动作

1. **先预测：** 读代码前写下输入、预计输出和可能失败处。
2. **自己实现：** 优先在贯穿项目里编码；参考教程只看当前所需章节。
3. **运行与改动：** 至少改一个输入或故意制造一个失败，观察行为是否符合预期。
4. **留证据：** 提交代码、测试输出和一段“本周踩坑/原因/修复”记录。测试绿灯之外，还要能口头解释。

- 每周只有 4 小时：按同样顺序把两周合为一个阶段，预计约 20 周；仍以过关标准决定是否前进。

本地 24 章是练习、代码与验收索引，外部成熟教程负责系统讲解。当前仅第 14 章已改成四节连续课程，其他章节的教案仍是初稿；学习时优先按本路线选择外部正文和本地练习。
