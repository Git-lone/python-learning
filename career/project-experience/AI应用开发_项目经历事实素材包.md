## 三、Spring AI 业务 Tool：把旧业务接口变成受约束的模型工具

### 背景与个人范围

商户通过 Agent 查询或办理税务资料，Agent 需要调用已有 Java 业务接口。旧接口包含国家、服务类型、服务单、操作身份和内部业务编码，不能把所有参数都交给模型自由填写。

本人在早期 `o-agent` 的 Spring AI 工具层有直接提交，工作包含英国 VAT 的账户校验、验证码二次校验、税号／EORI 校验、资料复用及 MTD 相关工具；另有公司注册、秘书及年审业务工具的开发记录。职责覆盖 Tool 定义、Feign 适配、工具元数据、参数组装和契约测试。

### 难点与具体处理

1. **模型知道的信息与后端可信参数不同。** 模型可能补错国家、服务类型或内部枚举。后续契约改造把服务单上下文、服务端身份、固定业务常量及可输入筛选条件分开处理；内部 MTD 类型和税局常量由工具构造，缺少关键业务上下文时不再默认成英国。
2. **工具描述正确，不等于调用正确。** 模型看到的参数说明、Java 方法签名、元数据迁移和 Feign 请求可能各自变化。本人同步调整这些位置，并增加契约用例，约束工具暴露字段与实际业务请求的一致性。
3. **同类接口存在不同国家与服务语义。** 用业务工具和请求适配承接这些差异，使模型只选择有明确业务意义的操作，参数转换与接口细节留在服务端。

简化链路：用户意图 → Agent 选择工具 → 业务参数与可信上下文组装 → Feign 调用 → 返回工具结果。模型路由与整个推理循环属于平台背景，本人直接贡献在工具与业务适配层。

### 已有产出与完成度

已形成业务 Tool、请求适配、元数据和契约测试的配套改动。原材料记载，初版账户校验及英国 VAT 工具被原版开发与 UAT 分支包含；后续参数收紧和公司／秘书工具扩展仅在个人开发分支见到证据，不能统一写成已生产上线。

本次再次核对了五条相关提交的作者与摘要。其中一条只是迁移脚本版本改名，属于同一功能的调整，不单独算新项目，也不把工具入口数量写成独立交付需求数量。

**可提炼表达：** 开发基于 Spring AI 的税务业务 Tool，完成旧接口适配、参数契约及工具元数据维护；区分模型输入、服务端身份与业务常量，并通过契约测试约束工具定义和实际请求的一致性。

**证据锚点：** `o-agent` 的 `e464d788`、`d5f171f2`、`396c5500`、`69e9cbe1`；`2f54d6b2` 是迁移文件版本调整。相关类包括 `VatUkApplyTools`、`VatUkTools` 及其 ContractTest。

## 四、Agent 工单：确认内容、执行结果与通知分别管理

### 背景与个人范围

商户通过自然语言创建工单，多轮补充、重复确认和网络重试都可能发生。Agent 可以重复交互，但业务写入需要有确定的归属和结果。

原审查记录用户确认参与这条业务链，使用“参与建设”。知识库同时指出核心工单实现有其他同事署名，现有材料不足以把全部一致性设计写成本人独立主导。上一节的本人 Tool 提交也不能替代本节的个人分工证据。

### 难点与具体处理

1. **确认后参数可能变化。** 业务层先根据服务端模板和服务单归属生成快照，固化待执行内容、请求标识、版本及有效期。确认执行时按快照重建参数，减少确认卡内容与实际落单内容不一致。
2. **跨服务不能依靠一个调用方事务防重。** 编排层负责准备和调用，拥有正式工单数据的服务同时保存幂等请求；在同一本地事务内完成请求状态 CAS 领取、工单及相关数据保存、成功状态更新，避免先记成功再远程落单的分离风险。
3. **HTTP 超时无法判断是否已创建。** 请求可能未到，也可能已经提交而响应丢失。调用异常后查询原请求的权威结果，无法确认时返回未知结果，本次调用不盲目再次创建。
4. **通知失败不等于落单失败。** 创建结果与通知结果分开保存和处理，避免通知异常让已成功工单再次进入创建流程。

简化链路：准备快照 → 用户确认 → 数据所属服务事务提交 → 查询权威结果 → 独立处理通知。

### 已有产出与边界

源码可追踪准备、创建、结果查询及最终事务。这里的幂等主要针对同一个请求，不自动等于“不同请求号表达的同一意图只建一单”。未知结果是调用方观察状态，不能推断数据库一定失败或一定保存了 UNKNOWN。

当前材料也不足以承诺通知最终送达、跨系统严格一次执行或所有环境均已启用。确认快照指纹不等于完整密码学签名验证。

**可提炼表达：** 参与 Agent 工单业务执行建设，通过确认快照、本地事务幂等和权威结果回查处理重复确认及跨服务超时；将通知状态与业务创建状态分离，避免辅助步骤失败触发重复落单。

**证据锚点：** 原 JD 审查中的参与记录；`AgentWorkOrderCreateServiceImpl`、`AgentWorkOrderCreateRequestServiceImpl`；学习知识库第一章和 `agent_execution_chain.md`。个人负责的具体设计、编码、联调范围仍待补充。

## 五、服务资料 AI：长任务、会话隔离与真实表单回填

### 背景与个人范围

多国税务资料存在动态模板、枚举和复合字段。AI 识别需要下载文件并调用模型，耗时超过普通接口；用户又可能重发、重置会话或修改当前表单。识别得到 JSON，并不代表能安全赋值或保存业务资料。

用户参与资料 AI 助手建设；可以明确展开的个人工作包括既有 Dify 工作流的英国业务场景扩展、字段规则适配、德国股东复合字段问题定位及 UAT 回填联调。异步任务平台核心有其他同事贡献，保留参与口径。

### 难点与具体处理

1. **模型输出与真实表单契约不一致。** 根据业务模板及 Vue 校验规则调整国家／服务类型路由，规范枚举和已验证的复合 JSON。排查时对照 Dify 输出、标准化结果和页面回填，定位错误产生在哪一层。德国股东信息被通用枚举校验误拒，是一个具体处理案例。
2. **同单多轮任务和消息重投交叉。** 本地消息保存状态，Redis 保存短期执行载荷，MQ 按服务单组织顺序投递；消费者通过数据库条件更新领取任务，完成时再次以预期状态保存结果。顺序投递和 CAS 分别解决调度顺序与并发领取问题。
3. **旧会话结果迟到。** 本轮交互标识关联消息与页面查询；消费与重置使用共同业务锁，重置后旧会话待办失效，结果写回仍需核验状态。补偿收敛排队和处理超时，迟到成功不应推翻本地终态。
4. **模型建议不能直接等价于业务成功。** 页面匹配实际存在的字段、归一化组件值并复用校验；已有值进入确认流程，模型建议与实际赋值反馈分别记录。识别成功、页面赋值、持久化保存和最终提交是不同结果。

### 已有验证与边界

原 UAT 记录覆盖 8 类服务，6 类通过、2 类部分通过，验证范围为识别、工作流输出与页面回填，没有覆盖最终保存或资料提交。它不能换算成模型准确率或全业务自动办理成功率；英国嵌套字段仍有历史回归问题，不能概括为所有复合字段均已解决。

异步模式在所读源码中默认关闭，运行还依赖环境开关、消息主题、消费者和补偿任务。DB、Redis、MQ 分别写入，不是一个原子事务；缓存丢失不能自动靠消息 ID 重建完整载荷。取消是本地状态约束，不等于撤销远端模型计算；请求超时后再次调用仍可能产生重复计算。

**可提炼表达：** 参与多国服务资料 AI 助手建设，结合 Dify 工作流、业务 Schema 与页面校验完成场景扩展和回填联调；围绕长任务状态、交互标识及结果写回条件治理重复请求和迟到结果，区分模型建议与用户实际修改。

**证据锚点：** `ai_features_evidence.md` 的 Dify 场景与 UAT 记录；`kb_ai_async.md`；`ServiceDataAiAsyncTaskService`、`ServiceDataAiRecordBizService` 及前端 `serviceDataAiPageMixin`。本节没有独立开发全部异步底座的证据。

## 六、LLM 企业资料识别：保住已取得的数据，再治理模型结果

### 背景与个人范围

税号查询需要访问有成本、有频率限制的外部服务，取得的公司地址又可能是非结构化文本。系统需要识别国家、匹配公司并同步税号，既不能让模型失败丢掉已付费获取的资料，也不能把模型答案直接当作权威业务结论。

本人负责基础采集、匹配与同步主链，并增加 DeepSeek 国家识别与补偿，配套运营后台也有本人提交。模型调用复用既有客户端，不是自研模型或模型网关。

### 难点与具体处理

1. **输出可解析，但业务关联可能错误。** 除 JSON 结构外，校验结果 ID、重复或陌生 ID、国家白名单和输入输出范围；歧义结果不强行选国。企业匹配和税号写入继续由规则与事务条件控制。
2. **模型缓慢或线程池拥塞拖累采集。** 将国家识别与已付费结果保存解耦，在资料提交后登记待办，由独立有界执行资源处理；执行队列拒绝时保留待办，避免在调度线程退化为同步模型调用，再由补偿继续识别。
3. **付费外部步骤与本地状态存在断点。** 在查询前做有效性预检，通过结果留存、检查点、锁、限流及失败补查控制恢复范围，尽量复用已有结果。主扫描、失败补查和后续匹配分别处理，减少整条流程无差别重跑。
4. **重复匹配或迟到处理可能覆盖新结果。** 使用状态、版本或代际条件复核处理对象；最终业务同步在数据所属服务中结合原值与状态更新，控制重复写入和已有税号覆盖风险。

简化链路：有效性预检 → 外部资料查询与保存 → 异步国家识别 → 规则匹配 → 事务条件同步。

### 已有结果与统计口径

原材料记录基础采集主链已生产运行，国家识别扩展进入 UAT。2026-11-16 追加核查确认，国家识别扩展已于 2026-11-03 首次进入远程现存 release-center 发布主线；此为代码合入证据，不等于完整部署版本证明。最新功能周期与生产聚合以《AI应用项目_实现机制与项目经历详解》为准。

历史核查截至 **2026 年 10 月 29 日**，公共采集累计覆盖 **32,320 个去重税号**，取得 **11,503 条公司信息**。这些数值是原核查留下的公共采集规模，未在本次重查；不是个人工时、LLM 识别准确率、自动回填量或成本节省。

外部已经收费而本地尚未留存就宕机，仍是需要恢复协议处理的边界，不能承诺彻底消除重复付费。现有材料没有模型与规则的统一标注集对比，也没有准确率、延迟、节省时间或费用改善的实测比例。

**可提炼表达：** 负责企业资料采集与核验链路，接入 LLM 处理非结构化地址国家识别，通过业务 ID、输出结构及白名单约束结果；将模型处理与已付费资料保存解耦，以有界异步执行、结果留存和补偿保护主链，最终写入保留规则校验和事务约束。

**证据锚点：** `ost-center` 的 `e6a0638484`、`9ff48ed191`、`993198539`；`DeVatCompanyCountryAiResolver`、`DeVatCompanyCountryService`、`DeVatCollectionService`、`DeVatMatchTransaction`；`ost_git_evidence.md` 与历史核查记录。

## 七、多国专利图像检索：从向量命中到可用业务结果

### 背景与个人范围

图片向量检索返回的标识与相似度不能直接用于商户展示。不同国家专利详情和法律状态不同，用户还需要筛选、分页和额度计次；详情补全可能打乱检索顺序，翻页也不应重复进行相同召回。

本人负责 Java 检索 API、图片向量与检索服务接入、多国详情编排及既有 Vue 页面适配。Milvus 和图片编码能力是调用已有服务，不是本人训练模型或独立建设向量数据库集群。

### 难点与具体处理

1. **逐国调用难以保持统一召回。** 把图片向量提取和相似检索拆开，对向量维度及两段超时分别控制；将所选国家作为集合提交给检索服务，完成一次向量联合召回，由上游统一生成顺序。
2. **标识与详情异构，补全后容易乱序。** 按国家策略转换字段与法律状态，以国家和 ST13 检索标识组成去重键，批量获取 Elasticsearch 详情，再按原命中位置恢复顺序。检索标识与 ES 文档主键不是同一概念；真正服务错误与文档确实缺失分别处理，不能把服务异常默默当作空数据。
3. **结果复用与计费口径相互干扰。** 分离整批检索快照和页级成功计次；快照按商户隔离，同一次检索的后续分页复用首次结果，保持原页级额度口径。国家或输入发生变化并不保证复用旧结果。
4. **新来源渐进接入与辅助故障。** 前后端读取同源国家配置，保护用户已选条件；处理空结果缓存，翻译异常允许降级，避免辅助能力失败导致整个检索不可用。

简化链路：图片 → 向量提取 → 联合召回 → 国家策略与 ES 详情补全 → 恢复命中顺序 → 快照与分页。

### 已有产出与边界

代码实现 7 个国家或地区的策略适配。历史记录中 UAT 实际启用过其中 6 个，不能将“实现 7 类适配”写成“7 国全部生产上线”。一次联合召回仅指向量检索请求，整个链路仍有独立图片提取、详情补全等调用。

这是图像检索应用工程，不是 RAG 问答、训练图像编码器或自研重排序模型。现有证据没有召回率、端到端耗时、生产 QPS 或成本改善比例。

**可提炼表达：** 负责多国专利图像检索业务接入，将逐国检索调整为一次联合向量召回，基于国家策略补全 ES 详情并恢复命中顺序；分离检索快照与页级计次，支持同次检索分页复用和渐进路由接入。

**证据锚点：** `ost-center` 的 `c51ca6357c2`、`af3de8e871f`、`ffc73d849d9`；前端 `d859853217e`、`eafe193ba0d`、`ac4d569f94a`；`ai_features_evidence.md` 与 `other_git_evidence.md`。后一个前端提交移除了早期翻译按钮，因此最终方案不再以该按钮组件为亮点。

## 八、配置驱动 RPA：扩展运行能力，并处理外部副作用

### 背景与个人范围

外部税局和公司注册网站的表单、文件和操作流程不同，执行耗时长。平台已有节点图、运行上下文和回调机制，本人负责业务编排、共享浏览器与文件能力扩展、执行可靠性及查册服务化，不能把整套引擎写为本人原创。

### 难点一：受控表单看似赋值成功，框架却未接收

普通 DOM 赋值可能只改页面可见值，未触发前端框架状态变化；单纯等待元素又不应该顺带点击。本人扩展 WebDriver 动作，通过原生 value setter 与输入、变更等事件同步状态，增加显式等待和空值跳过，将问题处理变成共享节点能力，供不同流程配置复用。

### 难点二：动态 PDF 没有稳定下载地址

确认文件由浏览器动态生成 Blob，常规网络地址下载不适用，系统“另存为”窗口也不适合服务端运行。新增 Blob PDF 解析器，在生成时捕获对象、读取字节并校验格式，上传对象存储后返回归档地址，解除对桌面操作和固定下载目录的依赖。

### 难点三：长任务结束时，业务可能已经进入新一轮

以服务单锁、活动执行批次和稳定请求标识约束重复触发；事务提交后再启动外部任务，执行或重试前复核当前业务节点。旧批次结束时按批次条件清理活动标记，避免迟到回调删掉新任务状态。这里复用了平台已有受理防重能力，属于业务执行生命周期治理。

### 难点四：提交成功与附件下载成功不是同一件事

历史问题是税局已显示申请成功，后置 PDF 获取失败却使整个任务判失败并再次申请。改造将外部业务成功与附件处理分开：已确认提交成功时保留成功结论和页面凭证，附件异常不再触发同类整项重提。若提交响应本身丢失，仍需核验外部结果，不能推广为所有未知结果都已解决。

### 难点五：查册资源与结果都需要分开管理

将既有查册能力迁入独立服务，Redis Set 保存登录凭证的 key 索引，通过共享轮询游标、稳定排序、过期索引清理和加锁补池管理多实例资源，替代读取凭证时扫描全键空间。旧材料曾概括为三阶段独立补偿和异步接入；本次源码复核修正为：公司信息与更名历史在同次查册中组合返回，截图有独立补偿通道；当前公司创建仍同步调用查册，账期初始化的异步片段已注释，不能将历史改动概括为当前均已异步。

### 已有产出与边界

材料支持三条开放的香港税局账号流程与内部履约节点衔接；第四类代码存在但禁用，不能计入开放流程。可陈述新增共享节点能力、服务端文件获取、提交与归档分离、凭证池治理和阶段补偿。

阶段补偿不等于通用引擎断点续跑，批次防重不等于外部税局严格一次执行。没有全平台月运行量、生产成功率或人工节省的实测指标。RPA 本身也是配置化流程，不自动等于自主 Agent。

**可提炼表达：** 参与配置驱动 RPA 体系建设，扩展受控表单输入、显式等待和动态 PDF 归档节点；通过执行批次、稳定请求标识及当前节点复核治理长任务与迟到回调，将已确认的外部提交和后置文件处理解耦，并完成查册服务化与阶段补偿。

**证据锚点：** `ost-center` 的 `c5fce85e3d`、`4223cc8c73`、`cd9719be16`；`acc-gst` 的 `4ca7398353`、`89ef059ad5`、`6c05fba96d`；`rpa_system_scope_evidence.md`、`project_rpa_highlights.md`。关键类包括 `HkTaxRpaManager`、`WebDriverNode`、`WebDriverBlobPdfDownloadParser`。

## 九、后端工程深度备选：财税快照与局部成功补偿

这部分可支撑五年后端经验，是否写进 AI 简历取决于岗位和篇幅，不必挤占前面所有 AI 项目。

### 财务档案与审计快照

实时公司和成员资料会变化，审计又需要知道某次业务完成时采用了哪些资料。本人新增独立档案模型，在完成审核时保存公司、董事股东及秘书资料快照；按字段差异生成变更记录，通过事务提交档案更新与日志，分离实时业务数据和历史交付依据。

已有结果是历史档案和修改依据可追溯，后续可接识别回写。初版以当时年份记录，后续才补充账期关联，不能写成从一开始就具备完整双时态版本系统。证据为 `acc-gst` 的 `2e8df17ce0`，来源 `finance_additional_evidence.md`。

### 跨账期同步的局部成功补偿

一次请求可能覆盖多个会计期间，外部系统部分创建成功后整体响应失败；简单判断“存在映射”可能漏建，整项重试又可能重复创建。本人建立本地与外部账期关联，重放时按成功映射过滤并继续处理剩余账期，审批文件和营业额同步携带具体目标账期，同时兼容历史报文。

已有结果是代码能识别部分完成并补建剩余对象，不能扩大为跨系统全局事务或任意故障严格一次。本次读取的实现还保留“已有数量等于请求数量即进入已完成路径”的判断，不能保证识别同数量但不同对象的情况。来源为 STAR 候选素材、`finance_additional_evidence.md` 及本次实际代码复核。

**可提炼表达：** 负责财税系统的档案快照与跨账期同步，事务化保存业务历史依据；针对外部批量操作部分成功的场景，以账期映射识别已完成对象并补处理剩余项，避免将局部成功视为整体完成。
