## 推荐独立扩展：工单草稿助手

选合成资料或有权使用的脱敏文档，禁止导出公司客户数据到个人仓库。MVP 只负责查询和生成草稿，发送由人工确认。无需为了展示 Agent 而自动退款、改库或处理支付。

1. 创建一份自己的需求说明：谁用、什么输入输出、明确禁止哪些行为、验收如何判定。
2. 从 API 把 request_id、身份和草稿传进持久化工作流；服务端校验审批者身份与 thread 归属，审批绑定草稿摘要。
3. 增加授权后的工单只读工具，允许的工具名与参数服务端白名单化；拒绝把模型内容当 shell/SQL 执行。
4. 替换或扩展检索，保留基线，在同一固定测试集上比较方案。不要边看测试答案边调参。
5. 注入一次服务重启、一次工具超时、一次跨租户请求和一次重复审批，保留脱敏结果。
6. 增加真实网络测试和并发压测，记录运行机器、并发、样本数、模型模式、版本、p50/p95、错误率与成本。没有模型调用时不能声称测到真实首 token 延迟。

## 展示包应该包含

- README：一条安装路线、一条离线演示路线、可选真实 API 的费用说明。
- 架构说明：数据流、信任边界、状态图；每个组件为什么存在。
- 测试证据：原始命令、日期、版本、样本量、失败情况，不只放绿色截图。
- 评测数据卡：来源与授权、脱敏方式、标签标准、划分、指标定义、已知局限。
- 决策记录：例如为什么先选单 Agent、为什么不先加向量库，什么证据会触发升级。
- 安全与运维说明：凭据注入、日志脱敏、最小权限、重试预算、报警、暂停自动执行和回滚方式。

## 简历措辞模板

可以写：`基于 Python、FastAPI、MCP 和 LangGraph 完成个人 Agent 工程练习，实现合成工单查询、审批恢复和幂等验证，并用 pytest 覆盖异常与权限边界。`

完成独立扩展后再增加自己的具体贡献。指标格式使用 `在 [数据集/环境]、[N] 条样本、[版本] 下测得 [指标]，相对 [基线] 变化 [结果]`，所有方括号必须由实际数据填写；不能把参考示例的 1.0 召回率写成生产准确率。
