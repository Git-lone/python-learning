# 第 24 章学案：发布门禁与证据

配合[本章讲解](README.md)使用。学会区分教学演示指标与真实发布证据。

## 生产就绪和发布门禁是什么

代码能运行只是最早的一步。生产就绪要求业务目标、错误率、延迟、费用、权限与恢复能力有可核查的证据。发布门禁把这些条件转成明确规则：指标无效先拒绝，安全失败作为硬约束，成功率和延迟按约定阈值判定。阈值需由真实业务与样本决定，不能把教学示例直接复制到线上。

## 技术栈与落地场景

本项目使用 `Decimal` 计算演示费用，使用测试报告、日志元数据和简单门禁函数说明验收思路。真实 Agent 服务还应将 request/run ID、模型和提示词版本、阶段耗时、工具状态、证据引用与用量关联到 trace；再通过固定评测集和线上监控观察回归。当前 API 仅有最小日志，没有实现完整 tracing、真实计费对账或生产级认证。

例如内部问答服务在发布前需要验证不同租户不会互见文档，断流不会显示为成功，模型失败有可追查请求 ID，成本指标包含失败与重试请求。任何一个关键权限用例失败，都不能被高平均成功率抵消。

## 代码怎样工作

[指标实现](../../agent_lab/operations.py)按传入的输入/输出单价与 token 数计算演示成本，用 `release_allowed` 一类规则决定是否放行。[练习](exercises/exercise_ch24.py)先拒绝 NaN、无限值、负数等无效指标，再比较成功率、p95 与权限失败次数。README 中的人为单价和阈值只是测试合同；作品集应明确区分实际实现、测试证据和未验证能力。
