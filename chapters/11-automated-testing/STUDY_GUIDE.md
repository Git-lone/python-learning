# 第 11 章学案：按合同写测试

配合[本章讲解](README.md)使用。先写预期，再查看被测实现。

## 自动化测试是什么

自动化测试把业务合同写成可重复执行的输入和断言。单元测试检验小范围规则，集成测试检验多个组件的协作；两者都应覆盖正常、边界和失败路径。测试不是“运行代码且没有报错”，而要明确验证返回值、异常或状态变化。

## 组成与使用场景

本项目用 pytest：普通函数作为用例，`assert` 表达期望，参数化覆盖代表值，夹具管理共享资源，`pytest.raises` 检查错误。对应 Java 的 JUnit/Mockito 经验。规则变化频繁、外部依赖不稳定时，测试替身可替代网络调用，但替身测试不能证明真实 API 一定可用。

例如折扣函数有下限 0，测试应直接写出“价格 10、折扣 15，结果为 0”，不要复制生产的 `max(0, price-amount)` 算期望；若实现公式写错，复制的期望也可能一起写错。

## 代码怎样工作

[示例测试](examples/test_pricing.py)准备价格和折扣率，调用[生产函数](examples/sample/pricing.py)，断言数值或异常。[练习](exercises/exercise_ch11.py)故意留下一个测试空缺，任务是证明固定折扣不会把价格降为负数，而不是修改被测函数。
