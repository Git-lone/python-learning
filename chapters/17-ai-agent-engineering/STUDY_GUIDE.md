# 第 17 章学案：手推 Agent Loop

配合[本章讲解](README.md)使用。每一轮记录“模型动作 → 应用处理 → 历史变化”。

## Agent 是什么

在本教程里，Agent 是围绕模型决策建立的受控循环：输入目标与历史，模型建议“调用工具”或“给最终答案”，应用执行允许的动作，把观察加入历史，再决定是否继续。它不是一次很长的提示词，也不意味着模型获得无限权限。固定步骤、规则明确的任务可用普通工作流完成；开放式下一步选择才可能需要 Agent。

## 技术组成与落地场景

最小 Agent 需要模型决策端口、动作类型、工具白名单、参数校验、历史、停止预算和结果对象。代码研究助手可动态选择搜索或读取文件，客服助手可在查询工单后再请求更多信息。生产中还要考虑权限、审批、时间与费用预算、提示注入、观测、状态持久化和结果验收；这些在第 18、21、24 章继续实现。

模型看见的检索文本和工具输出是数据，不应被当作高优先级指令。循环的终止条件也不能只依赖模型自报“做完了”；若任务包含副作用，需要独立确认实际结果。

## 代码怎样工作

[示例](examples/ch17_agent.py)第一轮由 `DemoModel` 返回 `ToolCall('add', ...)`，`run_agent` 在注册表中找工具并执行，把 `ToolObservation` 加入历史。第二轮模型读到观察后返回 `FinalAnswer`。未知工具成为拒绝观察，异常成为错误观察，超过 `max_steps` 则抛错。这里故意保持离线，让每轮状态可单步验证。
