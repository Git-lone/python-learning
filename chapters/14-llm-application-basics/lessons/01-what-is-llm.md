# 第 1 课：LLM 在做什么

> 本课约 20 分钟。先读两条客服消息，猜程序会如何分类；读完后能解释为什么模型有机会比关键词规则做得好，也能解释为什么它仍可能出错。

## 1. 从业务问题出发

假设工单系统只用 `"refund" in text.lower()` 判断是否转退款队列。下面两条消息会怎样？

```text
A. I was charged twice. Can I get my money back?
B. Please do not refund this order. I only need the invoice.
```

A 没有 `refund`，规则会判为 `other`；B 含有 `refund`，规则会判为 `refund`。但按客户真实意图，A 值得进入退款队列，B 不应该。问题不是 Python 字符串方法写错，而是**同一个意图可以有不同表达，词出现了也不代表用户肯定了这个意图**。

LLM（Large Language Model，大语言模型）可以在上下文中处理这些语言表达。它并不等于业务规则引擎，也没有读过本公司的最新退款政策。本课先理解它能提供什么，下一课再决定应用要补哪些部件。

## 2. 生成回答时发生了什么

常见生成式语言模型先用 tokenizer 把输入变成 token ID。token 可能是一个字、词的一部分、空格或标点；**token 数不能直接用汉字数或单词数代替**。模型接收 token 序列，计算下一个位置的候选分布，按解码策略选出新 token，接到末尾，再重复，直到到达停止条件或输出上限。[Hugging Face 的 LLM 入门](https://huggingface.co/learn/agents-course/en/unit1/what-are-llms)有这一过程的图解。

把它想成一次课堂推演，下面的数字只是说明“候选”这个概念，**不是任何真实模型的输出**：

```text
输入：客户说“我被扣了两次款，想退一笔”。输出开头：{"intent":"
下一段可能候选：refund（较高）、other（较低）
接着生成：refund"}
```

这也解释了为什么提示词里写“只返回 JSON”仍不能保证解析成功：生成过程可能提前结束、增加说明文字，或给出合法 JSON 但字段值不合法。模型越像“能理解人话”，越容易让开发者忘记返回值在程序眼里仍是一段需要验证的外部输入。

## 3. 模型为什么能处理不同措辞

训练阶段，模型从大量文本里学习语言和任务模式。Transformer 是现代 LLM 常见的架构；其中的注意力机制让一个位置在计算表示时参考其他位置。[Hugging Face 的架构导读](https://huggingface.co/learn/llm-course/chapter1/6)可用来继续学习编码器、解码器与注意力。对于应用开发，本章只需要抓住以下联系：

- `money back`、`refund`、`charged twice` 在具体语境中可能与退款请求相关，模型有机会利用上下文理解，而不必只看同一个词。
- `do not refund` 里的 `not` 会改变句意；只找 `refund` 这个子串会丢掉否定关系。
- “有机会理解”不等于保证理解。训练数据、提示词、上下文、模型选择都会影响结果；业务必须用样本评测。

**训练与推理要分开。** 训练改变模型参数；本教程调用已经训练好的模型产生结果，属于推理。把一段公司政策加入请求，是提供本次推理的上下文，不是在训练它。后面的 RAG 课会讲怎样检索这样的上下文。

## 4. 消息不是一整段随意拼接的字符串

在聊天式接口里，应用通常传递有角色的消息序列：

```python
messages = [
    Message("system", "Classify the user's intent. Return a JSON object."),
    Message("user", "I was charged twice. Can I get my money back?"),
]
```

`system` 是应用给模型的任务约束；`user` 是用户本次输入；`assistant` 通常用于保存模型此前回复。不同服务的消息格式可能不同，本章的 `Message` 是课程内部的数据类。把客户原文放在用户消息里，便于区分**应用指令**与**被分析的资料**。用户原文里即便出现“忽略上面的要求”，应用也不能把它当成可信的系统指令。

所有消息、检索资料、工具结果以及生成的回答都会消耗上下文预算。窗口大小由模型和服务决定；超出限制会报错或需要截断，未超限也不代表把所有历史塞进去就是好主意。应用需要保留和当前任务相关、经过授权的信息。第 16 章会处理外部知识，第 18 章会处理 Agent Loop 中的上下文管理。

## 5. 做一次判断

现在不写代码，回答三个问题，并记入[学案](../STUDY_GUIDE.md)：

1. A、B 两条消息中，哪条会被关键词规则判错？为什么？
2. 如果模型输出 `{"intent":"refund"}`，哪些条件满足了，哪些条件仍没有证明？
3. 客服说“按最新政策，订单 SO-1 能退吗？”时，模型凭自身文字生成能力能否证明订单和政策真实存在？

参考判断：A 是漏判，B 是误判；JSON 语法和字段出现并不能证明分类正确；订单事实与政策需要从有权限的系统获取并核验。

**本课产物：** 能用“token 序列生成 + 上下文理解 + 外部输入需校验”解释 LLM 在后端中的位置。下一课把它变成架构和技术选型。
