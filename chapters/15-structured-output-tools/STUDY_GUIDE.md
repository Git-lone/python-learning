# 第 15 章学案：结构化输出与工具注册

配合[本章讲解](README.md)使用，把模型提议与执行许可分开记录。

## 结构化输出与工具调用是什么

结构化输出要求模型按约定形状表达结果，例如 JSON 对象或工具名加参数。工具调用不是模型自己执行代码：模型生成调用建议，应用先解析和校验，再由本地处理器执行，把结果回送给模型或业务流程。即使输出符合 JSON 语法，字段类型、权限与业务规则仍可能不合法。

## 技术组成与落地场景

本章的最小技术栈是模型输出合同、JSON/数据校验、工具注册表、处理器和错误观察。客服可调用只读订单查询，财务可调用计算工具，开发助手可检索代码；对删除、付款和外发消息，还要加入审批与审计。MCP 是跨进程发现和调用工具的协议，在第 20 章出现；本章先学本地执行边界。

工具 schema 只应暴露模型完成动作所需的参数，不能把数据库连接或密钥放进参数。执行器必须先验证工具名和参数，再执行副作用；工具输出同样是不可信数据，需要在进入后续模型上下文前控制大小和内容。

## 代码怎样工作

[示例](examples/ch15_tools.py)接收固定结构的 `add` 调用，先通过注册表找到处理器，再检查两个参数是否为整数，最后执行加法。[练习](exercises/exercise_ch15.py)实现注册和分派，但具体 `add` 参数合同仍由处理器负责。未知工具不能退化为 `eval`、反射或任意 shell 调用。
